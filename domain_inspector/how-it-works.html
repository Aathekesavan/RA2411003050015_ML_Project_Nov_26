Public Surfaces

Audits what your server and domain publish to the public internet, observed from the outside.

  • ✓

    HTTPS and redirects

    Ensures all visitors are upgraded to encrypted connections with HTTP 301 redirection.

  • ✓

    Verifies certificate validity, trusted CA issuer, days to expiration, and modern TLS cipher suites.

  • ✓

    Security headers

    Audits Strict-Transport-Security (HSTS), Content-Security-Policy (CSP), and X-Frame-Options.

  • ✓

    Email security (SPF, DMARC, DKIM)

    Queries public DNS records to verify protection against domain spoofing and phishing.

  • ✓

    Server software fingerprints

    Identifies leaked software versions in HTTP Server and X-Powered-By response headers.

  • ✓

    Disclosed vulnerabilities

    Cross-references announced component versions against known security advisories.

  • ✓

    Cookie attributes

    Verifies Secure, HttpOnly, and SameSite attributes on session cookies.

  • ✓

    Public blocklist standing

    Checks if domain is flagged for malware, phishing, or deceptive practices.

  • ✓

    Checks for published security disclosure contacts at /.well-known/security.txt.

Questions & Details

Technical answers.

What exactly does SentinelX inspect?

What your website advertises to the internet: HTTPS redirection, TLS certificate validity and issuer, security response headers (HSTS, CSP, XFO, XCTO), DNS email records (SPF, DMARC), CAA records, cookie attributes, and RFC 9116 security.txt.

Will checking affect website performance or uptime?

No. SentinelX executes only a small number (< 10) of standard, polite HTTP HEAD/GET and DNS queries, indistinguishable from a regular visitor opening your homepage in a browser.

What is outside the scope of an exterior check?

SentinelX focuses on the perimeter. It does not authenticate with user accounts, crawl pages behind logins, perform exploit attempts, run denial-of-service tests, or access internal mail server infrastructure.
